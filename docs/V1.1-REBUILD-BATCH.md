Original batch list (file:line references are v1.0.0):

## License / activation (the batch's reason to exist)

1. **LicenseGate: add a recovery link.** `src/components/LicenseGate.jsx:132-142`
   offers only "Don't have a key? Buy ALAN Echo" — a customer who reinstalled
   Windows and lost the email is funneled toward buying a second copy. Add under
   the buy link: `Lost your key? Recover it → https://alanglobalintelligence.com/echo/recover`.

2. **Open external links in the real browser.** The gate's buy anchor is plain
   `target=_blank`, which WebView2 opens as a chromeless popup — no address bar,
   no password manager, exactly where a buyer types card details. The shell
   plugin is already initialized (`main.rs:523`) and permitted
   (`capabilities/default.json:26`): switch the anchor to
   `window.__TAURI__.shell.open(url)`.

3. **Surface persistence failure at activation.** `main.rs:118-128`
   `validate_license` does `let _ = s.save();` — if the settings write fails
   (disk full, AV blocking %APPDATA%), the app says "License activated" but
   re-gates on every launch. Return `{ valid: true, persisted: false, message }`
   and have LicenseGate warn.

4. **Gate the Rust commands, not just the React render.** Enforcement today is
   one frontend boolean: `check_license` is consulted only by `main.jsx`, and
   every backend command (start_recording `main.rs:147`, transcribe `main.rs:287`)
   is invocable unlicensed. Add release-build `Err` returns on `start_recording`
   + `transcribe` when `!state.license.lock().is_licensed()` (mirror the debug
   bypass at `main.rs:132-134`). Keep the frontend fail-open (it protects paying
   users on IPC hiccups) but log it.

5. **Back up settings.json alongside transcripts.** The key's only durable copy
   is `%APPDATA%\ALAN Echo\settings.json`; `db.rs:185-195` backs up only
   transcripts.db. Include settings.json in the daily backup, and on corrupt
   settings load (`main.rs:475-478`) restore from the newest backup before
   falling back to fresh.

6. **Key-input polish.** `LicenseGate.jsx:33-49`: multi-line pastes containing
   "ALAN Echo" latch onto the ECHO inside "ALANECHO" — regex-match
   `/ECHO([A-HJ-NP-Z2-9]{20})/` (last match) instead of first `indexOf("ECHO")`.
   When validation fails and the input contains O/0/I/1/L, hint that Echo keys
   never contain those characters.

7. **Secret-list support (forward compatibility).** `license.rs:38-57` checks a
   single SECRET. Change `validate_key` to try a slice `[SECRET_V1]` so a future
   build can append a V2 secret while old keys keep validating. Trivial diff,
   zero behavior change today.

## Release process for v1.1 (site side is already wired)

- Build, then update Vercel env **together**: `ECHO_DOWNLOAD_URL` (new asset URL)
  + `ECHO_INSTALLER_SHA256` (new hash). Emails and the success page point at
  `/api/echo/download`, so published links never go stale.
- Upload installer + SHA256SUMS.txt to the release; VirusTotal-scan both assets
  and put the permalink in the notes.
- In-app "download GPU pack" button is the top 1.x feature after this batch
  (site already serves `/api/echo/download/gpu`).

## SECRET rotation runbook (operational, no code)

- The v1 HMAC secret (`license.rs:16`, mirrored in
  `stock-analyzer/lib/echo/license.ts`) is **permanent for all of v1.x**.
  Rotating it bricks every paying customer who updates while pirates simply
  don't update. If a keygen circulates: respond with NOTHING app-side — that is
  the accepted cost of offline validation.
- A future paid major version (v2) uses a NEW secret + key prefix, so v1 keys
  are naturally rejected there. Item 7 above keeps the door open for additive
  secrets without breaking old keys.
